# 初始项目的数据流

```text
app.py 创建配置、模型客户端、数据库和 ChatService
    ↓
终端输入（以后增加微信输入）
    ↓
ChatService.reply(user_id, text)
    ├─ SQLite 取当前用户最近 20 条历史消息
    ├─ 人设 + 历史 + 本轮输入 → messages
    ├─ DemoClient / DeepSeekClient 生成回复
    └─ 一个 SQLite 事务保存本轮问答
    ↓
终端输出（以后增加微信输出）
```

`persona/` 中的四个 Markdown 文件被合并成一条 system 消息。近期历史保存在
`data/chat.db`，重启后仍保留。长期记忆目前手工维护，没有自动抽取、向量检索或总结。
API 失败不会保存不完整的一轮问答。

初版采用同步调用，方便逐步调试。微信事件、并发会话和调度接入时，再明确队列和异步边界。
模型调用是外部 HTTP 服务；微信服务端同样属于外部系统，本地调试可以观察请求、响应和状态。

当前已经实现：终端入口、离线模型、DeepSeek HTTP 客户端、人设加载、SQLite 历史。
预留但尚未实现：微信登录收发、自动长期记忆、主动消息调度、后台服务。
